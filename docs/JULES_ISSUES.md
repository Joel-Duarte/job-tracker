# Jules issue automation

Connect this repository to the [Jules GitHub App](https://jules.google/docs/running-tasks/) and add a Jules API key from [Jules settings](https://jules.google/docs/api/reference/authentication/) as the GitHub Actions repository secret `JULES_API_KEY`. The connected Jules account needs access to this repository. The workflow discovers the Jules source and its default branch through the API.

When an open issue is created with the `bug` label, or that label is added later, the workflow starts a read-only validation task. A maintainer with repository write access can comment `/jules validate` to retry validation or `/jules fix` to start a fixer directly. Other comments, PR comments, and feature issues do not start tasks. An explicit `/jules fix` is a maintainer override of the reproduction gate.

The validator must report concrete reproduction steps or a failing test. A scheduled workflow checks task results every 15 minutes. Confirmed bugs start a separate Jules fix session with automatic PR creation. Inconclusive validation or a failed fix is reported on the issue with suggested next steps. Jules and GitHub Actions may take longer than 15 minutes to complete or start a poll; check the linked Jules session for progress.

The workflow uses `jules:validating`, `jules:fixing`, `jules:needs-info`, and `jules:done` labels to track progress. GitHub Actions creates these labels when first needed. Do not add the `jules` label for this flow: Jules' native GitHub integration treats that label as a separate trigger and would start an extra task.

The validator's verdict is generated by Jules, so treat it as triage evidence. Review the linked session, proposed regression test, CI results, and PR before merging. The workflow cannot guarantee that Jules will never create an unsuitable PR; its instructions explicitly reserve PRs for fixes.

Security alerts use a separate manual workflow. In **Actions → Jules security fix → Run workflow**, choose `codeql` or `dependabot` and enter the alert number from the repository Security tab. The workflow accepts an open alert on `master`, creates a Jules session, and puts its link in the run summary. This session does not enable automatic PR creation. Review the result before publishing a fix, and keep sensitive vulnerability details out of public issues and PRs. Rotate or revoke leaked credentials before considering any code change.
